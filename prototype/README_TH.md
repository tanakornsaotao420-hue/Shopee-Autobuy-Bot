# Campaign Planner 0.2 — ต้นแบบจำลองสำหรับ Windows

รายละเอียดการปรับจาก repository เดิมและขอบเขตงานอยู่ใน [ADAPTATION_TH.md](ADAPTATION_TH.md)
รุ่นนี้เพิ่มการตรวจ snapshot สุดท้ายก่อนส่งคำสั่ง และสถานการณ์ผิดบัตร/ผิดสินค้า/ข้อมูลเก่า

โปรแกรมเดสก์ท็อปสำหรับเตรียมรายการซื้อและทดสอบ Workflow แคมเปญ
**ไม่เชื่อม Shopee ไม่เปิดเว็บ ไม่สั่งซื้อ และไม่หักเงินจริง**
ไม่มี API key และไม่มีแพ็กเกจภายนอกที่ต้องติดตั้ง

## เปิดใช้งาน
1. ติดตั้ง Python 3 พร้อม Tcl/Tk และ Python Launcher หากยังไม่มี
2. แตก ZIP ไปยังโฟลเดอร์ที่เขียนไฟล์ได้
3. ดับเบิลคลิก START_WINDOWS.bat หรือรัน `python app.py`
4. ใช้ค่าตัวอย่างก่อน ค่าเริ่มต้นจะตั้งเวลาอีกประมาณ 2 นาที
5. เลือกสถานการณ์แล้วกด “บันทึกและตั้งเวลาจำลอง”
6. เลือกงานในตารางเพื่อดูประวัติผล เมื่อรอยืนยันหรือไม่ทราบผล กดปุ่มจำลองผลได้

เวลาที่กรอกเป็นประเทศไทย เช่น `2026-11-11 00:00:00` ไม่ขึ้นกับ timezone เครื่อง
ตัวอย่างส่วนลด DEMO300 เป็นข้อมูลสมมติ ไม่ใช่คูปอง Shopee
ส่วนลดเป็นจำนวนเงินรวมที่กรอกเอง ไม่มีเครื่องคำนวณสิทธิ์คูปองจริงในเวอร์ชันนี้
ราคาต่อชิ้นคูณจำนวน บวกค่าส่ง หักส่วนลดรวม = ยอดจำลอง
ไม่หัก Coins/เงินคืนในอนาคตออกจากยอดชำระ

## สิ่งที่ทดสอบได้
- ตั้งเวลาและกำหนดเส้นตาย งบต่อคำสั่งซื้อ และงบรวมตามชื่อแคมเปญ
- สินค้าหมด โค้ดหมด ราคาเกินเพดาน บัตรปฏิเสธ การรอยืนยัน และผลไม่ชัดเจน
- เก็บข้อมูลใน simulation.sqlite3 ที่โฟลเดอร์โปรแกรม เปิดใหม่แล้วอ่านงานเดิม
- สถานะ UNKNOWN และ WAITING_USER ยังกันงบไว้ จนระบุผลแน่นอน
- งานเดิมไม่ส่งซ้ำ แม้เปิดโปรแกรมใหม่ หยุดงานได้ก่อนส่งคำสั่งจำลอง
- บันทึกใหม่ถือเป็นเจตนาสร้างงานใหม่ จึงซื้อจำลองซ้ำสินค้าได้หากยังอยู่ในงบ

## ข้อจำกัด
- ต้องเปิดเครื่องและโปรแกรมไว้ ไม่มี background service หรือการปลุกเครื่อง
- นาฬิกาอิงเครื่องผู้ใช้ ตรวจเวลาทุก 1 วินาที ไม่รับประกันความแม่นยำระดับมิลลิวินาที
- ไม่แก้ไข/ลบแผนที่บันทึก ให้หยุดแผนเดิมแล้วสร้างใหม่
- ชื่อแคมเปญเดียวกันต้องใช้งบรวมเท่ากัน ยอดสำเร็จยังถูกนับในงบ
- เลขคำสั่งซื้อขึ้นต้น SIM- เป็นเลขจำลอง ไม่มีสถานะจัดส่งจริง
- ไม่กรอกข้อมูลบัตรเต็ม CVV OTP รหัสผ่าน หรือที่อยู่จริง ใช้ชื่อเรียกเท่านั้น
- ผ่านการทดสอบ engine อัตโนมัติ แต่ยังไม่ได้ทดสอบหน้าต่างบน Windows จริง

## ก่อนเชื่อมซื้อจริง
ต้องยืนยันช่องทางที่ Shopee อนุญาต และความสามารถซื้อของฝั่งผู้ซื้อก่อนเลือกเทคโนโลยีเชื่อมต่อ
เวอร์ชันนี้ไม่มีตัวเชื่อมต่อหรือปุ่มเปิดซื้อจริงซ่อนอยู่
ตรวจรุ่นสินค้า ที่อยู่ ยอดรวม สิทธิ์คูปอง และบัตรที่เลือกก่อนส่งคำสั่ง
เมื่อเครือข่ายขาดหลังส่งคำสั่ง ต้องตรวจคำสั่งเดิม ไม่ส่งใหม่อัตโนมัติ
OTP/การอนุมัติธนาคาร/CAPTCHA ต้องมีจุดส่งต่อให้ผู้ใช้ ไม่ข้ามการยืนยัน
ขอบเขตอัตโนมัติเต็มรูปแบบขึ้นกับช่องทางที่ได้รับอนุญาตและการยืนยันของผู้ให้บริการ

## สำหรับพัฒนาต่อ
`engine.py` คือ state machine + SQLite; `app.py` คือ Tkinter UI
ทดสอบด้วย `python -m unittest -v`
เพิ่ม adapter ที่ได้รับอนุญาตภายหลัง โดยต้องแยก submit/reconcile และเก็บ intent ก่อนเรียกภายนอก
ธุรกรรม SQLite ใน simulator ไม่สามารถรับประกัน exactly-once ของระบบชำระเงินจริงได้
